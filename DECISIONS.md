# PokerGym — DECISIONS.md

**Версия: v16**

Технические и продуктовые решения по проекту — что решено и почему. Хронология конкретных находок и багов живёт в git (сообщения коммитов), здесь — только действующие правила и контракты. Ссылки на ID компонентов — см. таблицу в `ARCHITECTURE.md`.

## Разбиение на файлы — общие правила
- ES-модули, не `<script>`-теги. `import` не работает на `file://` — нужен локальный сервер при разработке.
- **Правило самодостаточности.** Каждый переданный результат — пара «вынесенный кусок + обновлённый остаток, который на него ссылается», никогда кусок сам по себе (реальный инцидент: CSS был вынесен без переписанного `index.html` — «проверка» ничего не проверяла). Единица работы — наименьший набор файлов, при котором результат реально запускается и тестируется, не обязательно один файл из таблицы.
- Три отдельных роутера, не один: `router.js` (вкладки + «назад», общий), `practice/practice-router.js` (под-экраны Практики), `theory/theory.js` (под-разделы Теории).
- `core/state.js` — чистое хранилище, без импортов из фич-модулей (риск циклических зависимостей). Другие модули подписываются на изменения сами, не наоборот.
- `practice/trainings/` — плоская папка: без подпапки на каждую тренировку, без группировки по категориям хаба (та классификация — UI/педагогическая, не структура кода).
- `-logic.js`/`-ui.js` — только для тренировок заметно больше ~150–200 строк; сейчас ни одна не разделена (см. Backlog в `ARCHITECTURE.md`). Критерий чистоты: если в логике встречается `document.getElementById`/`innerHTML` — код не в том файле.
- Перед написанием кода новой тренировки — сначала проверить `core/`/`ui/`, не копировать, если похожее уже есть.
- **Мёртвого кода быть не должно** (кроме явных временных заглушек, обозначенных как таковые). Если ветка условия или сохранённое значение перестали быть достижимыми через UI — убирать сам код, а не оставлять «на всякий случай»: реальный инцидент — убрали опцию «Без ограничения» у показа карт, но сначала оставили проверку `showTime === "none"` в коде как «безобидную»; она не только не нужна, но и маскирует реальную деградацию для пользователей со старым сохранённым значением (см. ниже, «Показ карт»).

## Методология проверки
- `node --check файл.js` (без флагов) ненадёжен для ES-модулей — может показывать «всё чисто» на файлах, которые падают в браузере. Использовать `node --input-type=module --check < файл.js`.
- Этого тоже недостаточно — не ловит несовпадение импорт/экспорт и логические ошибки. Обязательна полная имитация браузера через `jsdom` (загрузка настоящего `index.html`, реальные клики по интерфейсу) перед сдачей любого объединяющего шага.
- **Отдельный класс бага: используемая переменная не импортирована и/или не экспортирована.** И `node --check`, и беглое чтение кода его не ловят — переменная просто не определена в области видимости, ошибка всплывает только в момент реального обращения к ней в браузере (`ReferenceError`), причём может быть скрыта: если это происходит внутри обработчика клика до строки, открывающей модалку/применяющей результат, внешне выглядит как «кнопка ничего не делает», а не как явная ошибка. Найдено трижды за один заход: `cardId`/`suitColor`/`displayRank` использовались в `outs.js` без импорта (ломало модалку «Разбор»), `TRAINING_WEIGHTS`/`REAL_PROBS` использовались в `combinations.js` без экспорта из `outs.js` (ломало модалку сравнения с реальными вероятностями), `RANKS` использовалась в `outs.js` без импорта (ломало генерацию стрит-флеша/рояля в «Комбинациях» на подуровне «5 карт»/«флоп» — рояль падал 100% раз, стрит-флеш ~89%). Проверять таким же образом при любой находке «кнопка/модалка не работает» без явного текста ошибки в консоли.
- **Не мутировать массив, на который могут ссылаться другие места, без `.slice()`.** `shuffle()` (Фишер-Йетс) меняет переданный массив на месте. Если передать общую константу напрямую (как было с `POS_LADDER_OLD[n]`) — она необратимо портится при первом же вызове, и баг проявляется не сразу, а спустя один-два раунда/переиспользования. Тасовать копию: `shuffle(arr.slice())`, если исходный массив используется где-то ещё.
- **При переименовании функции — искать вызовы по всему проекту (`grep`), не только там, где сам ожидаешь их найти.** При объединении `posShuffle`/`notPickRandom` в общие `shuffle`/`pickRandom` пять вызовов со старыми именами остались незамеченными в двух файлах — упали только в узком сценарии (вопрос о вероятности в «Матрице префлопа»), не входившем в обычный набор кликов при проверке.
- **Тестировать не только настройки по умолчанию, но и реже используемые ветки (переключатели вкладок/чекбоксы).** Два реальных бага (`DRAW_TYPES`/`OTHER_OUT_TYPES` без импорта, целиком пропавшая при нарезке `createCategoryChip`) не проявлялись, пока тестировался только дефолтный сценарий «Аутов» — вскрылись только при явной проверке ветки `wantCategory: true`, которая по умолчанию выключена.
- **Жалоба «генератор случайности ведёт себя нечестно» — проверять расчётом, не на глаз.** Дважды разбирали такую жалобу (частоты категорий в «Комбинациях», число игроков в «Позициях») — в обоих случаях сам генератор (`pickTargetCategory`+`TRAINING_WEIGHTS`, `randomInt`) оказался статистически чистым при прогоне на тысячах итераций вне браузера (Node, без DOM — все задействованные функции чистые). Реальная причина одной из жалоб — сосед­ний, не связанный с рандомом баг (см. `RANKS` выше), вызывавший зависание экрана и создававший иллюзию повторов. Хи-квадрат/Монте-Карло тест на присланных пользователем сырых данных — рабочий способ отличить реальный перекос от шума малой выборки, не полагаться на интуицию ни со своей, ни с его стороны.
- **Спорные «точные» цифры от третьей стороны — не принимать на слово, проверять пересчётом и контрольной суммой.** Дважды присылали «исправленные» вероятности с якобы точными формулами — оба раза ошибочными (наивные комбинаторные формулы без учёта пересечений между категориями, см. `combo-generation.js` выше). Простой и надёжный тест: сумма по всем взаимоисключающим категориям обязана равняться общему числу сочетаний; у ошибочных наборов не билась (расхождение на десятки-сотни тысяч), у выверенных полным перебором — сходилась ровно.
- **Двойное округление — реальная ошибка, не теоретическая.** При огрублении строки флеш-рояля в модалке вероятностей (см. «Комбинации — доработки» ниже) первая попытка взяла уже отображаемое округлённое значение («0.00015») и округлила его ещё раз — результат разошёлся с округлением истинной точной дроби (0.0001% вместо верного 0.0002%), потому что (а) округление уже округлённого числа само по себе может дать другой результат, чем округление точного значения, и (б) 0.00015 не хранится в JS-float точно, а как число чуть меньше, из-за чего `.toFixed()` качнулся не в ту сторону. Вторая попытка (отдельная функция `fmtProbCoarse`, независимый поиск «сколько знаков даёт ≥1 живую цифру») тоже ошиблась — не воспроизвела то же самое, что «взять результат обычного правила и убрать один знак», а нашла математически другую короткую запись (0.001 вместо 0.0009) из-за округления вверх на более грубом шаге. Верный подход: всегда весь путь округления — от точного значения один раз, либо явно «взять точность обычного правила и отнять один знак» через ту же самую точку отсчета, никогда не округлять то, что уже когда-то округлили.
- **Аудит на неиспользуемые импорты — сделан один раз вручную по всем 23 файлам проекта** (`practice/trainings/`, `core/`, `ui/`, `settings/`, и т.д., кроме `js/lib/sortable.js` как сторонней библиотеки). Метод: для каждой строки `import { ... } from "..."` (с учётом многострочных и `as`-алиасов — проверять нужно локальное имя после `as`, не оригинальное экспортируемое, иначе ложные срабатывания) проверить, встречается ли каждое импортированное имя ещё где-то в файле; каждое найденное совпадение перепроверено `grep`-ом вручную, не только скриптом. Нашлось и убрано 7 случаев в 5 файлах (`outs.js`: `RANK_VALUE`, `computeOuts`; `positions.js`: `RANKS`, `SUITS`, уже были в оригинале до текущей сессии правок; `preflop-grid.js`: `RANKS`; `calc-equity.js`: `RANKS`, `SUITS`, `openCardPicker`; `equity-worker.js`: `RANK_VALUE`). Метод не строгий (regex по границам слов, не AST-парсер) — не гарантирует, что поймал всё, и не заменяет такую же проверку при следующих содержательных правках.

## Контракты, зафиксированные при интеграции
- **Роутер — реестр коллбэков, не прямые импорты.** `onSubviewShow(name, fn)` / `onAnySubviewShow(fn)` в `practice-router.js`: тренировка сама регистрирует, что делать при показе своего экрана. Роутер не импортирует тренировки напрямую — иначе циклический импорт (тренировки и так импортируют `showSubview` из роутера).
- **`ui/card.js`: `cardEl(card, faceUp, faceStyle, cardBack)`** — стиль колоды и рубашка параметрами, файл не импортирует `core/state.js`.
- **`core/session.js` — чистый стейт-менеджер, без DOM.** `createSession`/`recordAnswer`/`isSessionComplete`. Формат результата хода:
  ```js
  { trainingId: string, isCorrect: boolean, userAnswer: any, correctAnswer: any, timestamp: number }
  ```
  Подготовлен и проверен, но пока не подключён — `outs.js`/`positions.js`/`combinations.js` считают счёт по-старому, чтобы не менять поведение попутно с переносом файлов. Понадобится к Этапу 5 (Статистика).
- **`core/equity-worker.js`** — модульный воркер (`{ type: 'module' }`), импортирует `hand-eval.js`/`deck.js` напрямую, без дублирования кода. Путь к самому файлу воркера считается на стороне `calc-equity.js`, через `new URL('../../core/equity-worker.js', import.meta.url)` — не жёсткий путь, не сломается при деплое в подпапку (например, GitHub Pages без своего домена). При аудите неиспользуемых импортов найдено расхождение с собственным же комментарием файла («дублирования нет, всё импортируется») — `RANKS`/`SUITS` были продублированы локальными константами вместо импорта из `state.js`; поправлено, значения были идентичны, поведение не изменилось.
- **`evaluate7` переименована в `evaluateBest`** — функция универсальна для 5/6/7+ карт через `combinations(cards, 5)`, не жёстко на семь.
- **Калькулятор аутов не делит состояние с тренировкой «Ауты».** В оригинале — общие переменные `currentDeal`/`currentClassification` (общая область видимости позволяла). Теперь — собственные `calcCurrentDeal`/`calcCurrentClassification`, поведение калькулятора не изменилось.
- **DTO раздачи для Обучариума.** Функции генерации раздачи (`dealNewHand`, `dealNewPositionsRound`, `dealNewCombo` и т.п.) при следующей содержательной правке каждой конкретной тренировки должны получить опциональный параметр «готовая раздача извне» — не сделано ещё ни в одной, закладывать по одной, не разом.
- **Точка входа для Обучариума — построена.** `startTraining(moduleId, customSettings)` + реестр `registerTrainingEntry` в `practice-router.js`. Каждая из 5 сессионных тренировок экспортирует `applySettings(settings)` и регистрирует себя при загрузке модуля. Точные формы `settings` — см. `ARCHITECTURE.md`, конец «Плана игры»; теперь включают `hideCards`/`showTime` у «Аутов» и «Комбинаций» (см. «Показ карт» ниже) — собственно ради этого перенос и затевался.

## Показ карт — построено (своя настройка каждой тренировки)
- **Было:** `hideCards`/`showTime` жили в `global`-секции `localStorage`, единые на всё приложение, поле существовало только у «Аутов». Проблема — Обучариуму нужно запускать тренировку с преднастроенной опцией показа, не трогая общую настройку остальных тренировок; плюс «Комбинациям» такая опция была нужна отдельно.
- **Стало:** `hideCards`/`showTime` — часть собственных настроек каждой тренировки (`outs`/`identifyCombo` секции `localStorage`), тот же контракт снимок+Ок/Отмена в шестерёнке, что и у остальных полей. `global`-секция эти поля больше не хранит.
- **Вкладка «Настройки» — не отдельное хранимое значение, а «применить обеим тренировкам сразу» + расчётный статус-бар.** Чекбокс/чипы там при изменении пишут значение напрямую в `outs` и `identifyCombo` (через экспортированные `persistOutsSettings`/`persistCombinationsSettings`). Под ними — нередактируемая строка «Везде одинаково» / «В тренировках разное» (`refreshCardDisplayStatus` в `settings.js`), которая **не хранится**, а пересчитывается заново сравнением текущих значений `outs`/`identifyCombo` при каждом заходе на вкладку (хук в `router.js`). Осознанное решение: третье, отдельно хранимое поле статуса создавало бы риск рассинхрона (тот же класс проблемы, что уже дважды случался с визуальными переключателями и `localStorage`, см. ниже) — вычисляемое значение рассинхронизироваться не может по конструкции.
- **«Комбинации» — ревил построен с нуля** (раньше там не было вообще никакого скрытия). Прячется **только рука** (2 карты), **борд виден всегда** — прямое продуктовое решение, тот же принцип, что в «Аутах». Реализация 1:1 с `outs.js`: показ лицом вверх → если включено — таймер → переворот рубашкой вверх по истечении → зажатие/клик на руке временно показывает снова.
- **Подуровень «5 карт» в «Комбинациях» — деления на руку/борд нет вообще**, скрытие туда не натягивается. Блок «Скрывать карты» в шестерёнке для этого подуровня дизейблится и визуально затемняется (`row-disabled`), само сохранённое значение при этом не сбрасывается — вернётся, если переключить подуровень обратно.
- **При проверке ответа (`check-answer`/чек «Комбинаций») рука принудительно раскрывается и таймер глушится**, если ещё была скрыта — иначе не видно подсветку использованных карт при разборе, а срабатывание таймера могло бы случиться уже во время просмотра результата. Правка сделана в обеих тренировках одинаково (изначально забыл про «Ауты», добавил по прямому замечанию — тот же баг был в обоих местах).
- **Опция «Без ограничения» времени показа — убрана целиком** (из UI и словаря во всех трёх местах: вкладка «Настройки», обе шестерёнки). Она была функционально идентична простому выключению «Скрывать карты после показа» — в обоих файлах условие пропуска ревила было одно и то же (`!hideCards || showTime === "none"`), то есть два способа получить одно и то же поведение. Заодно освободило чипсы времени от переноса на второй ряд (было 5 чипсов, стало 4 — `min-height: 76px` под второй ряд в CSS тоже убран как более не нужный).
- **Миграция старых данных: не мигрируем, просто игнорируем невалидное значение.** У пользователей, успевших сохранить `showTime: "none"` до удаления опции, `applySettings` теперь явно пропускает это значение (`if (settings.showTime !== undefined && settings.showTime !== "none")`) — откатывается к дефолту («3»), а не пытается его интерпретировать. Без этой проверки: в UI не подсвечивался бы ни один чипс (ни один `data-value` не совпадает с `"none"`), а `parseFloat("none")` дал бы `NaN` в расчёте времени таймера. Тот же принцип, что уже зафиксирован для схемы `localStorage` в целом (см. ниже) — расширен на уровень отдельного поля, не только версии секции целиком.
- **Ярлык переименован:** «Скрывать карты после показа» → «Прятать руку после показа» (RU), одна строка в словаре, действует на обе тренировки — точнее описывает, что реально происходит (борд не прячется никогда, прячется только рука).

## Генератор раздачи по категории — `core/combo-generation.js`
- **Было:** `pickTargetCategory`, `generateCardsForCategory` и таблицы вероятностей (`TRAINING_WEIGHTS`, `REAL_PROBS`) физически жили в `outs.js`, хотя тренировка «Ауты» их не использует вообще — ни разу, ни прямо, ни транзитивно (подтверждено `grep` по вызовам, не на слово). Единственный настоящий потребитель — `combinations.js`, импортировавший их оттуда.
- **Почему это плохо:** `practice/trainings/` — папка «один файл = одна тренировка»; хранить в файле одной тренировки код, нужный только другой, создаёт скрытую связь, которая будет только хуже с новыми потребителями (уже сейчас ясно, что «Теория» в будущем тоже захочет эти же вероятности — см. ниже).
- **Стало:** весь кластер вынесен в `core/combo-generation.js` — чистая логика без DOM, импортирует только `core/state.js`/`core/deck.js`/`core/hand-eval.js`. `outs.js` полностью очищен от него (не просто помечен как «не используется» — физически убран). `combinations.js` импортирует из нового файла напрямую, не через `outs.js`.
- **Точные вероятности для 5/6/7 карт (`REAL_PROBS_5`/`REAL_PROBS_6`/`REAL_PROBS`)** — не Монте-Карло, честный подсчёт: 5 карт — полный перебор всех C(52,5)=2 598 960 комбинаций, 6 карт — полный перебор C(52,6)=20 358 520 (обычная брутфорс-формула через «36 баз × 47 карт» и подобные ей даёт систематическую ошибку из-за двойного счёта/пересечений между категориями — разобрано на реальном споре в чате, наивная формула ошиблась на порядок для редких категорий), 7 карт — сверено с независимым источником (durangobill.com, классические точные данные). Сумма по всем 10 категориям контрольно равна общему числу сочетаний — простой и надёжный способ проверить набор чисел целиком, не по одной строке.
- **Формат вывода вероятности — минимум 2 «значащие» цифры после запятой**, где ноль, идущий после ненулевой цифры, тоже считается значащим (`fmtProb()` в `combinations.js`): обычные проценты остаются на 2 знаках, редкие (флеш-рояль на 5 картах и т.п.) получают ровно столько знаков, сколько нужно, не больше и не меньше.
- **Модалка вероятностей — одна таблица на все три количества карт**, не три отдельные модалки. Колонки: 5 карт / 6 карт / 7 карт (точные) + тренировочная (`TRAINING_WEIGHTS`, одна и та же для всех улиц по замыслу — генератор выбирает целевую категорию раньше, чем знает, сколько карт в итоге раздаст). Под таблицей — одна сноска: что такое «тренировочная» вероятность (вторая, про соответствие «5/6/7 карт» улицам, убрана по прямому решению Романа как избыточная).

## Комбинации — доработки
- **Борд отображается первым (сверху), рука — вторая (снизу)** — было наоборот, поменяли местами по прямому продуктовому решению. Логика скрытия/пика привязана к DOM-элементу руки, а не к его позиции в разметке — порядок в `area.appendChild(...)` не влияет на остальную механику.
- **«Подуровень» переименован в «Улица»** — тот же термин, что уже был в «Аутах» для аналогичного выбора (Флоп/Тёрн). Единственная неидеальность — вариант «5 карт» не улица в строгом смысле (нет борда/руки как таковых), но как заголовок группы кнопок слово остаётся достаточно точным, отдельно этот вариант не переименовывался. **Найден и починен хвост старого названия**, пропущенный при самом переименовании: статичный текст в `index.html` (`setting-label` перед `.sublevel-grid`) всё ещё гласил «Подуровень» — ключ словаря `setup.sublevel` был переведён на «Улица» давно, но JS перезаписывает этот текст только после применения языка, а сама HTML-разметка так и осталась со старым словом. Тот же класс проблемы, что уже случался с рассинхроном названий в чате — правится по мере нахождения, не системным аудитом (для чисто текстовых констант в разметке такого аудита и не может быть, только глазами/по прямой жалобе).
- **Кнопки «Улицы» — 4 в один ряд** (`.sublevel-grid`: `grid-template-columns: 1fr 1fr 1fr 1fr`), высота уменьшена (`padding` кнопки 14px→8px по вертикали). **Перенос текста — принудительный, сразу после «+»** (`Рука+флоп` → `Рука+` / `флоп`), не перенос по словарю. Раньше здесь был тот же `hyphens: auto`, что и у «Комбинации» на плитке хаба (см. «Перенос по словам» ниже) — на практике браузер иногда предпочитал перенос по слогу в неожиданном месте вместо переноса по границе «+». Решение: сама строка словаря (`setup.sublevelFlop`/`Turn`/`River`) содержит настоящий перевод строки сразу после «+», кнопка — `white-space: pre-line` (переносит по `\n`, схлопывает обычные пробелы как всегда). Детерминированно, не зависит от эвристик hyphenation-словаря браузера. `hyphens:auto`/`overflow-wrap:break-word` для этого селектора убраны — не нужны при принудительном переносе.
- **Точность в модалке вероятностей — фиксированное число знаков по строке, не вариативная.** До фулл-хауса включительно (idx 0-6) — 2 знака, Каре — 3, Стрит-флеш и Флеш-рояль — 4. Относится только к трём столбцам точных вероятностей (5/6/7 карт, `fmtProbExact`); тренировочная колонка не тронута — там осталась прежняя вариативная точность (`fmtProbByRow`/`fmtProb`/`fmtProbCoarse`, «минимум 2 живые цифры», Флеш-рояль на 1 знак грубее). Раньше на точные столбцы тоже действовала вариативная точность (`fmtProb` для Каре/Стрит-флеша, `fmtProbCoarse` для Флеш-рояля) — заменено на фиксированную по прямому решению Романа: для читаемости и предсказуемости в конкретно этих трёх столбцах важнее не разброс точности, а стабильное число знаков.
- **Заголовок колонки «Тренировочная» — перенос по словам** вместо обрезки без многоточия (слово не помещалось в узкую фиксированную колонку `table-layout:fixed`). Первой версии не хватило места — переносилось в 3 строки, а не 2. Пересчитано по реальным замерам ширины текста (Python/PIL, шрифт с запасом шире реального iOS-шрифта — то есть расчёт консервативный, в реальности должно быть свободнее): `font-size` таблицы 12px→11px, первая колонка (название комбинации, с переносом и заголовка «Комбинация» тоже) сужена до 19%, три числовые колонки (5/6/7 карт) — по 20%, «Тренировочная» — 21% (было 18.5% у всех четырёх поровну). Высота строк данных увеличена до 42px, чтобы вместить редкий перенос без разной высоты строк.

## Позиции — доработки
- **Название тренировки не менялось** — остаётся «Позиции за столом» везде (хаб, шапка сессии, глоссарий «Теории»). Поправлен только заголовок собственной модалки настроек — был рассинхронизирован («Настройки: Позиции», без «за столом»), теперь совпадает с остальными местами.
- **Номера над креслами — убраны.** Это был просто порядковый индекс в массиве координат (`POS_SEAT_COORDS`, место 0 — «ты», дальше по часовой), не позиция за столом и не подсказка — подсветка активного кресла уже показывает, куда отвечать. Не несли игровой информации, оставлены явно как технический артефакт разработки раскладки. Заодно убран CSS-класс `.pos-seat-num` как ставший мёртвым кодом.
- **Формат Кратко/Полно разблокирован для русского языка.** Раньше был жёстко заперт на «Кратко» при `state.lang === "ru"` — решение было продуктовым (для английского разница «UTG vs Under The Gun» ощутимее в живой речи, чем «Андер» короткое/полное), отменено по прямому решению Романа. Функция `updatePosFormatAvailability()`, которая делала это блокирование, убрана целиком вместе со всеми вызовами (не оставлена пустышкой) — теперь переключатель просто всегда активен для обоих языков.
- **Термины позиций (RU) переименованы** — те же ключи словаря, что использует и полный формат «Позиций», и глоссарий «Теории»: Смолл-блайнд→Малый блайнд, Биг-блайнд→Большой блайнд, Андер→УТГ, Андер+1/Андер+2→УТГ+1/УТГ+2, Лоджек→Лоуджек, Кооф→Кат-офф. Переименовано сознательно и в «Теории» тоже — общая терминология по всему приложению. Заодно найдена и поправлена утечка старого термина внутри текста определения (`term.utg1.def` на русском ссылался на «андера» прямым текстом, не через ключ).
- **Число игроков — `<select>`, не степперы.** Степперы были опробованы (см. предыдущая версия документа) и откачены обратно по прямому решению Романа — визуально не понравились. Урок не в самом откате (это нормальная итерация), а в том, что решение UI-виджета для этого конкретного места оказалось не с первого раза — если тема снова всплывёт, начинать сразу с варианта «аккуратный `<select>` в одну строку», не пробовать степперы заново без новой причины.
- **«Формат отображения» переименован в «Формат записи»** — точнее описывает, что меняется (запись имени позиции, не визуальное отображение чего-то ещё).

## Мнемоника — построено

- **Три фазы в одном под-экране** (`session-mnemonic`), переключаются видимостью блоков, не отдельными под-экранами роутера — тот же принцип, что у скрытия руки в «Аутах»/«Комбинациях»: минимум новых сущностей в `practice-router.js`.
  1. **Показ** — 2 карты рубашкой вверх → лицом вверх на заданное время → рубашкой вниз. Автоматический переход к отвлечению по истечении времени, без ручного «дальше».
  2. **Отвлечение** — серия арифметических примеров подряд (сложение/вычитание, результат неотрицательный), каждый на своём таймере. Ошибся или не успел — серия сбрасывается на 0, генерируется новый пример (не тот же самый). Раздача карт всё это время не меняется.
  3. **Вспомнить** — те же 2 слота, что и в калькуляторах (`renderSeqCardRow`/`openCardPicker`, `ui/card-picker.js`), маска занятых карт строится из уже заполненных слотов — выбрать одну и ту же карту дважды физически невозможно, отдельный код для этого не понадобился.
- **Показ карт — сознательно урезанный вариант общего контракта**, без тумблера «скрывать/не скрывать»: рубашка после времени показа наступает всегда, прямое требование из чата. Поэтому `mnemoState` хранит только `showTime`, не `hideCards` — не третья копия поля, которого нет по смыслу.
- **Интеграция с общей настройкой «Показ карт» на вкладке «Настройки» расширена с двух тренировок до трёх.** Блок «применить всем сразу» теперь пишет `showTime` и в `mnemonic`-секцию (не пишет `hideCards` — у «Мнемоники» такого поля нет). Расчётный статус-бар (`computeCardDisplayStatus`) тоже трёхсторонний: «одинаково» требует, чтобы «Ауты» и «Комбинации» сами скрывали карты (`hideCards: true` у обеих — раз «Мнемоника» скрывает всегда, при выключенном скрытии у остальных двух они принципиально разные) и чтобы время показа совпадало у всех трёх. Осознанное решение, не техническая случайность: без этого условия статус мог бы показать «одинаково» в ситуации, где одна тренировка ведёт себя иначе двух других по самой механике, не только по цифре времени.
- **Настройки тренировки** (модалка, контракт снимок+Ок/Отмена, как у остальных четырёх): время показа (общий шаблон чипов), разрядность чисел (двузначные/трёхзначные, `digitLength`), число примеров подряд (`exampleCount`, сегмент 3/4/5), время на один пример (`exampleTime`, свой набор чипов — крупнее, чем у показа карт: 5/8/12 сек, арифметике нужно больше времени, чем на запоминание двух карт).
- **`stopMnemoTimer`/`stopMnemoExTimer` — два независимых таймера, оба глушатся при уходе с вкладки/экрана** (`router.js`, по образцу `stopTimer`/`stopComboTimer` у «Аутов»/«Комбинаций») — иначе таймер отвлечения мог бы сработать и сбросить серию уже после того, как пользователь ушёл с тренировки.
- **Хаб-плитка снята с заглушки** (`isStub: true` убран из `HUB_MODULES`, id `mnemonic` добавлен в список прямого запуска через `startTraining` в `hubOpenModule`) — тренировка теперь открывается по клику, как остальные пять сессионных.

## Мнемоника — доработки по первому реальному тестированию
- **Ввод ответа на арифметику — экранная клавиатура, не `<input>`.** Раньше тап по полю открывал нативную клавиатуру устройства, а дальше приходилось выбирать между кнопкой приложения «Проверить» и клавишей «Done» самой клавиатуры — двусмысленно и медленно (прямая жалоба из чата). Теперь под примером — сетка кнопок 0–9 + backspace + кнопка отправки, всё внутри страницы, нативная клавиатура не открывается вообще. Кнопка отправки называется «Ответить», не «Проверить» — то слово уже занято другим действием в этой же тренировке (проверка выбранных карт в фазе «Вспомнить»), совпадение названий в двух местах одного экрана путало бы. На десктопе то же самое дублирует физическая клавиатура (цифры/Backspace/Enter) — те же три функции (`mnemoAppendDigit`/`mnemoBackspace`/`mnemoSubmitAnswer`), просто второй источник вызова; слушатель `keydown` активен только пока реально показана фаза отвлечения (проверяется по видимости `#mnemo-phase-distract`), чтобы не перехватывать ввод в других частях страницы.
- **Порядок выбора карт в «Вспомнить» не имеет значения** — проверено по коду, не только на словах: сравнение идёт по множеству id карт (`recallIds.every(id => dealIds.has(id))`), не по позиции слота. Выбрать верную пару в любом порядке — не ошибка.
- **Подсветка правильно/неправильно и показ верного ответа — приведены к общему виду с остальными тренировками.** Раньше не было вообще никакой подсветки при верном ответе, а при неверном — только текст с символами масти («Было: 5♣ 6♠»), в другом формате, чем сама тренировка (отрисованные карты). Теперь: слоты в `#mnemo-recall-slots` подсвечиваются `.field-correct`/`.field-incorrect` — теми же классами, что уже используются в других полях приложения, не своим изобретением; при ошибке верный ответ показывается такими же отрисованными картами (`cardEl`), как в фазе показа, а не текстом.
- **Отступ между полем ответа и полосой времени примера.** `.timer-bar-track` рассчитан на отступ сверху от предыдущего элемента (сам даёт только `margin-bottom`) — строка с ответом (`.mnemo-example-row`) отступа снизу не давала, эта комбинация просто не встречалась раньше в таком порядке. Не патч поверх общего класса `.total-answer-row` (использовался бы и другими местами) — отдельный `.mnemo-example-row` с собственным отступом, специфичный для этого экрана.
- **Настройка «Примеров подряд» переименована в «Количество примеров»** — точнее (речь не о содержании подряд, а именно о числе).
- **«Секунды» в подписях времени примера приведены к уже сложившемуся сокращению.** Старые чипы показа карт (0.5/1/3/5 сек, использовались ещё до «Мнемоники») в английском — компактные «0.5s»/«1s»/… Новые чипы времени примера (8/12 сек) на английском были добавлены как «8 sec»/«12 sec» — разнобой. Приведены к «8s»/«12s», не наоборот (переписывать три устоявшихся места ради двух новых было бы куда инвазивнее).

## Плитки хаба — перенос по слогам сужен, но не до одного случая
- **`hyphens: auto` был слишком щедрым**: браузер вставлял перенос по слогу даже там, где слово прекрасно помещалось на вторую строку целиком без всякого переноса («positions», «calculation» — тот же класс проблемы, что раньше нашли на плитке «Расчёт эквити», просто тогда почитали её единичным случаем и патчили точечно одну плитку исключением. Оказалось — не единичный.
- **Логика перевёрнута**: по умолчанию `.hub-card.compact .hub-title` теперь `hyphens: none` (перенос только по границе слова через `overflow-wrap: break-word` как механическая подстраховка), а `hyphens: auto` включён точечно только там, где слово физически не помещается в 2 строки без разбивки внутри себя: «Комбинации»/«Combinations» (`[data-module="identify-combo"]`) и «Мнемоника» (`[data-module="mnemonic"]`). Прежнее исключение для «Расчёт эквити» (`hyphens: none` поверх общего `auto`) убрано за ненадобностью — теперь это и есть значение по умолчанию.
- **Список составлен эмпирически, по факту жалоб, не по формуле длины слова.** Первая попытка (см. выше) ограничилась одной «Комбинации» — оказалось недостаточно: без `hyphens:auto` «Мнемоника» переносила одинокую «а» на отдельную строку (`overflow-wrap:break-word` без словаря выбирает точку разрыва механически, не по слогам — тот самый некрасивый случай, ради которого изначально и вводили `hyphens:auto`). Если найдётся ещё такая плитка — добавлять в этот же список по факту, не пытаться заранее вывести общее правило по числу букв.

## Настройки — язык статус-бара «Показ карт»
- **`#card-display-status` не обновлялся при переключении языка**, пока пользователь не заходил на вкладку «Настройки» заново. Причина: его текст не статичный `data-i18n`, а вычисляется отдельной функцией `refreshCardDisplayStatus()` (зависит от состояния трёх тренировок, не просто перевод одной строки) — общий обход `[data-i18n]` внутри `applyLanguage()` этот элемент не видит и не трогает. Тот же класс бага, что уже фиксировался с визуальными переключателями: восстановление/пересчёт значения само не синхронизирует то, что отрисовывается отдельным шагом. Починено — `refreshCardDisplayStatus()` вызывается прямо из `applyLanguage()`, не только по хуку захода на вкладку в `router.js` (тот хук остался, это дополнительный вызов, не замена).

## Настройки — расстояние между свотчами рубашки/лица/фона стола
- **`.preview-row` (общий класс для рубашки карт, лицевой стороны, фона стола) — увеличен зазор** (8px→14px) и отступ подписи от превью (4px→6px), по прямому впечатлению «слиплось» из чата. Названия рубашек («Красная классика» и т.п.) не сокращались — сознательно, по прямому решению: короче не значит аккуратнее, решили раздвинуть, не резать текст.
- **Настоящая причина разнобоя в выравнивании подписей — не зазор, а ширина.** `.chip-label` была 44px (по ширине самой рубашки), без `overflow-wrap`. Короткие подписи («Синяя классика», «Красный ромб») укладывались и центрировались нормально; длинные («Красная классика», особенно однословный «Минимализм» без точки переноса) физически не помещались в 44px и вылезали за границы коробки без переноса — отсюда и казалось, что часть подписей «съехала» влево, хотя `text-align:center` был на месте у всех одинаково. Починено: `.chip-label` расширена до 64px, добавлен `overflow-wrap: break-word` — центрирование внутри `.swatch-col` (`align-items:center`) не зависит от того, что подпись теперь шире самой рубашки, обе колонки остаются выровнены друг под другом.

## Мнемоника — вторая волна правок после первого реального использования
- **Дисплей набранного ответа держал фиксированный размер только в теории.** `.mnemo-answer-display` был `<span>` (строчный элемент) — `min-width`/`min-height` на строчных элементах браузер игнорирует по спецификации CSS, поэтому пустая коробка держалась почти на одном padding и заметно меняла размер при первой введённой цифре («всё прыгает» из чата). Починено: `display: inline-block` + фиксированные (не `min-`) `width`/`height` — теперь размер вообще не зависит от содержимого, тот же принцип, что у обычного `.total-answer-input` в других тренировках.
- **Отступы клавиатуры/примера увеличены по прямому впечатлению «слипается».** `.mnemo-keypad` margin-top 4px→20px (не липла к пустой, но всегда резервирующей место строке ошибки над ней). Текст примера (`#mnemo-example-text`) увеличен (22px, полужирный) и получил вертикальные поля вокруг себя (`.mnemo-example-row` margin 12px сверху/20px снизу) — карточка была не заполнена, место было.
- **Фаза «Вспомнить»: сначала пробовали разместить обратную связь под кнопками — не понравилось (см. чат), переделано на макет «карты рядом».** Порядок в разметке был «карты → кнопки → текст ошибки → верные карты» — решало проблему прыгающей кнопки, но выглядело плохо (правильный ответ отображался ниже кнопки, оторванно от собственных выбранных карт). Заменено на: слоты выбора и верный ответ (при ошибке) — рядом в одной строке (`.mnemo-recall-row`), под строкой — текстовый вердикт «Верно»/«Неверно» (`.mnemo-verdict`, зарезервированная высота, как раньше у текста ошибки), кнопка — ниже вердикта с увеличенным отступом. Ширина колонки под верный ответ (`.mnemo-correct-cards`) зарезервирована постоянным `min-width`/`min-height`, не только когда там реально есть карты — тот же принцип «ничего не прыгает», что и раньше, просто теперь применён к горизонтали, а не только к вертикали.
- **Подсветка верно/неверно была тоньше, чем в остальных тренировках.** `.field-correct`/`.field-incorrect` меняют только цвет рамки; у карточного слота рамка 1.5px — на глаз заметно тоньше подсветки в других местах приложения (там обычно 2px+). Добавлено точечное `.card-slot.field-correct`/`.field-incorrect { border-width: 2px; }` — не трогая базовое правило (используется и в калькуляторах, где толщина устраивала).
- **Дисплей ответа — пересчитан под глобальный `box-sizing: border-box`.** Первая правка (`display: inline-block` + фиксированные `width`/`height`) исходила из content-box-логики — но в проекте действует глобальный `border-box`-сброс (см. запись про `.switch-track` в «Шапка и шестерёнка настроек»), из-за чего заявленные `height: 20px` уже включали padding и рамку, а не складывались с ними: на сам текст оставалось около 2px, коробка выходила раздавленной («кривое поле» из чата). Пересчитано под реальную модель (`height: 38px`, явный `box-sizing: border-box`), центрирование переведено на `display:flex` вместо расчёта на совпадение `line-height` с высотой бокса.
- **«Минимализм» в подписи рубашки переносился так же некрасиво, как раньше «Мнемоника» на плитке хаба** — тот же класс бага (перенос без словаря оставляет одинокую букву), тот же фикс: `.chip-label` получила `hyphens: auto`.

## Ауты, Матрица префлопа — доработки и найденный баг
- **Названия сокращены**: «Ауты и вероятность»→«Ауты», «Матрица префлопа и вероятность диапазона»→«Матрица префлопа» — везде (иконка хаба, шапка сессии, заголовок модалки настроек уже был короткий, не трогался).
- **Коллизия названий: калькулятор аутов переименован в «Калькулятор аутов».** Он и раньше назывался просто «Ауты» — пока тренировка называлась «Ауты и вероятность», разницы не было видно, но после сокращения названия тренировки до «Ауты» два разных хаб-тайла (в разных группах — «flopturn» и «calculator») стали бы называться одинаково. Не входило напрямую в исходный запрос — добавлено по факту находки, не молча.
- **Оба калькулятора переименованы ещё раз, стилистически: «Калькулятор аутов»→«Расчёт аутов», «Эквити»→«Расчёт эквити».** Второй раунд правки того же названия за одну сессию — нормально, не повод считать первое переименование ошибкой, просто более точная формулировка нашлась не сразу.
- **«Что показывать» (Матрица префлопа) переименовано в «Тип тренировки»** — то же слово, что уже используется в «Нотации» для похожего по духу выбора (формат вопроса, не этап раздачи). Сознательно НЕ унифицировано с «Улицей» «Аутов»/«Комбинаций» — это разные оси (этап раздачи vs формат вопроса), одно слово на оба исказило бы смысл хотя бы для одной пары.
- **Suited/Offsuit в настройках «Матрицы префлопа» — переведены**: Одномастные/Разномастные. Не новые слова — те же, что уже в `term.suited.ru`/`term.offsuit.ru` в глоссарии «Теории», просто во множественном числе (как соседние кнопки «Пары»/«Микс»).
- **Текстовая дробь «⁄» (U+2044) заменена на обычный слэш «/».** Символ визуально слипался с соседними цифрами в большинстве шрифтов — был выбран когда-то, видимо, из стилистических соображений («настоящий» дробный слэш), но издержка перевесила пользу.
- **Найден и починен баг: модалка «Разбор» в «Аутах» не открывалась.** `renderBreakdown()` использовала `suitSymbols[card.suit]`, а `suitSymbols` — приватная (неэкспортированная) константа в `ui/card.js`, нужная только для `cardEl()`. Клик по «Разбор» падал с `ReferenceError` до строки, открывающей модалку — она никогда не показывалась. Тот же класс бага, что уже чинился в этом же файле (`cardId`/`suitColor`/`displayRank` без импорта) — но другая переменная, найденная только по прямой жалобе «модалка не открывается», не по общему аудиту (см. `BACKLOG-08` в `ARCHITECTURE.md` — аудит на неиспользуемые импорты по конструкции не ловит переменные, которые вообще не пытались импортировать). Починено экспортом `suitSymbols` из `card.js`.

## Раскрывающие элементы и мелкая вёрстка
- **Три «раскрывающие стрелки» в приложении** (не больше — проверено по всему коду): `.hub-group-chevron` (группы вкладки «Практика»), `.eq-breakdown-toggle` (разбивка по комбинациям в калькуляторе эквити), `.glossary-term summary::after` (термины «Теории», нативный `<details>` с кастомным маркером вместо `-webkit-details-marker`). Первые два — одного увеличенного размера (22px), глоссарий — увеличен меньше (18px), по прямому указанию не делать все три одинаковыми.
- **Диммирование кнопок-ответов «Матрицы префлопа» (числовой выбор) чинилось отдельно от подсветки.** `.pos-option-btn:disabled { opacity:.35 }` — общее правило, не различавшее «просто неактивна» и «уже подсвечена как верная/неверная»: правильный (зелёный) вариант гас вместе с остальными тремя после ответа, из-за чего все четыре выглядели одинаково блёкло. Добавлено исключение `:not(.answer-correct):not(.answer-incorrect)`.
- **Калькулятор эквити: селектор итераций и кнопка «Пересчитать» — равная ширина.** Было `flex:1` у блока итераций и `width:auto` у кнопки (по тексту) — асимметрично. Теперь оба `flex:1`.
- **Плитки хаба — перенос длинных слов + одинаковая высота.** Проблема с обрезкой «Комбинации» без «…» — не баг `-webkit-line-clamp` как такового, а то, что это одно длинное слово без пробелов, и без разрешения на перенос внутри слова браузеру буквально некуда его перенести на вторую строку. Добавлены `hyphens: auto` + `overflow-wrap: break-word` на `.hub-card.compact .hub-title`, плюс `min-height: calc(1.25em * 2)` — резервирует место под заголовок всегда в 2 строки, даже если реальный текст короче, чтобы плитки в одном ряду не отличались по высоте из-за разного числа строк в подписи.

## Перенос по словам — `hyphens: auto`
- **Выбран `hyphens: auto` (настоящий перенос по слогам с дефисом через языковой словарь браузера), не только `overflow-wrap: break-word`** (механический разрыв без дефиса и без учёта слогов, только когда слово совсем не помещается). Второй остаётся как подстраховка на случай, если браузер не найдёт точку переноса в словаре для конкретного слова.
- **Зависит от корректного `lang`.** Нашли смежный, независимый баг: `<html lang="ru">` был статичным, JS менял только `state.lang`, атрибут `lang` у `<html>` не обновлялся никогда при переключении языка — то есть при английском интерфейсе браузер пытался бы переносить английский текст по русским правилам. Починено: `applyLanguage()` в `settings.js` теперь синхронизирует `document.documentElement.lang = state.lang` при каждом вызове (каждое переключение языка и при первой отрисовке).
- Применено пока точечно, не глобально: `.hub-card.compact .hub-title`, `#probs-modal-table th` — там, где конкретно была реальная проблема с обрезкой/непомещением текста. Не добавлено «на всякий случай» по всему приложению. `.sublevel-grid button` (кнопки «Улицы» в «Комбинациях») из списка убран — там перенос теперь принудительный после «+» через `white-space: pre-line`, не через словарь браузера (см. «Комбинации — доработки»); `hyphens:auto` там больше не используется.
- **Точечное исключение внутри `.hub-card.compact .hub-title`: плитка «Расчёт эквити» (`[data-module="calc-equity"]`) — `hyphens: none`.** Двухсловный заголовок («Расчёт эквити») не нуждается в переносе по слогам вообще — перенос по границе слова (после пробела) и так укладывается в отведённые две строки. Браузер тем не менее иногда предпочитал перенос по слогу внутри «эквити» — по прямой жалобе Романа отключено для этой конкретной плитки. Общий `hyphens:auto` для остальных (в первую очередь «Комбинации» — однословный заголовок без пробелов, для которого перенос по слогам и был изначально введён, см. выше) не тронут.

## Работа с репозиторием из чата (без Claude Code)
- Project Knowledge (Документы проекта) не годится для активно редактируемого многофайлового проекта: либо грузит всё целиком в контекст ниже ~200К токенов, либо нечёткий RAG-поиск выше. `ARCHITECTURE.md`/`DECISIONS.md` — небольшой ориентир там, сам код — точечно.
- Рабочий способ чтения кода: `bash_tool` (обычный `curl`), не `web_fetch`. `web_fetch` может читать только уже встречавшиеся в разговоре URL — ограничение безопасности, действует с момента появления инструмента. `bash_tool` — отдельная песочница с доступом к `github.com`/`raw.githubusercontent.com`/`api.github.com`/`codeload.github.com` без этого ограничения:
  ```
  curl -s "https://raw.githubusercontent.com/Ramzesikus/PokerGym/main/путь/к/файлу"
  ```
  `api.github.com` (список файлов одним запросом) подвержен общему лимиту запросов на IP — при отказе просто повторить позже, или сразу читать файлы напрямую через `raw.githubusercontent.com`. Требует публичного репозитория.
- **Правки без Claude Code отдаются как готовые изменённые файлы (полный текст), не как диффы** — Роман сам кладёт их поверх локальных файлов и пушит. Диффы в чате полезны для быстрого review отдельных строк, но не заменяют выдачу файла целиком по прямому запросу.
- **Изменения в коде проверяются статически (`node --check`) и, где возможно, расчётом/симуляцией вне браузера** (см. «Методология проверки») — живого браузера у модели нет, полноценный `jsdom`-прогон с кликами по всему `index.html` в этом режиме работы обычно недоступен (нет под рукой всего дерева файлов разом). Реальную проверку в браузере после применения правок делает Роман.

## Claude Code
- Работает напрямую с файлами на диске, `CLAUDE.md` в корне читается автоматически. Доступен из терминала, десктоп-приложения, браузера, мобильного приложения. Рекомендуется изоляция при автономном режиме — простаивающая VM с Ubuntu в VirtualBox. Сессия не видит переписку в обычном чате. Пока не переходим.

## PWA
- PWA = сайт + `manifest.json` + service worker. Сейчас ни того, ни другого нет. Известная болячка — обновление закэшированной версии без продуманного версионирования. Поддержка PWA у Apple менее стабильна, чем у Google/Android.
- **Порядок этапов (PWA — Этап 6, после наполнения контента) — подтверждён сознательно, не пересматриваем.** Технической зависимости нет (Обучариум/Статистика могут быть заглушками на момент внедрения PWA, кэш-лист просто расширится позже), но есть трудозатратная: service worker требует дисциплины на каждый деплой (не забывать обновлять версию кэша), иначе классический баг «запушил — а у пользователя всё равно старая версия». Дешевле ввести эту дисциплину, когда фичи устаканятся и деплои станут реже, а не сейчас, в фазу самых частых правок (как раз предстоящая работа над Обучариумом/Статистикой/тренировками-заглушками).

## Деплой
- Деплой происходит по `git push`, не по каждому визиту. Публичность репозитория и публичность сайта — независимые вещи. Минификация — часть сборки, которой сейчас нет в проекте. Файлы репозитория при деплое остаются нетронутыми.

## Приватность репозитория
- Публичный репозиторий, пока в нём только клиентская логика — риск низкий. Автоматические боты сканируют все публичные репозитории на предмет секретов — секреты не коммитить никогда. Закрыть репозиторий — когда появится код авторизации/оплаты.

## Целевая архитектура ресурсов
- Три слоя: хостинг статики → сервер API → база данных. Начинать с управляемых отдельных сервисов, не с одного своего сервера.

## localStorage — построено (Этап 2)
- Формат — JSON, один ключ (`pokergym_settings`), версия схемы внутри данных (`version: 1`). При несовпадении версии — не мигрируем, откатываемся к дефолтам для несовпавшей секции, не пытаемся героически восстановить. Тот же принцип теперь применяется и на уровне отдельного поля внутри секции (см. «Показ карт» — невалидное `showTime: "none"` игнорируется точечно, не всей секцией).
- Хранит только настройки/предпочтения (`global`, `hub`, `outs`, `positions`, `notation`, `preflopTable`, `identifyCombo`) — не прогресс и не текущую раздачу/сессию. `global` больше не хранит `hideCards`/`showTime` (переехали в `outs`/`identifyCombo`, см. «Показ карт»). Данные аккаунта (подписка, прогресс, статистика) — источник правды сервер/БД, ждут Этапов 4/5/8.
- `core/storage.js`: `loadSection(key)`/`saveSection(key, data)`. Пишет немедленно при каждом изменении, не батчит. Каждое обращение — в `try/catch`, приложение обязано полностью работать даже при недоступном `localStorage` (приватный режим и т.п.) — деградация до текущего поведения без сохранения, не крах. Проверено включая полностью отсутствующий `localStorage` (не только квоту).
- **Важный урок, тот же класс ошибки, что уже был с чекбоксами при разработке**: восстановление значения в `state`/`posState`/и т.п. не синхронизирует само по себе визуальные переключатели на экране (`.active`-класс кнопок, `checked` у чекбоксов, `aria-label`) — это отдельный шаг, который легко забыть. Нашли и почему-то ещё раз наступили на грабли с кнопкой компакт-режима хаба — она определяется в файле позже, чем восстановление данных, синхронизация визуала вынесена отдельной строкой сразу после объявления кнопки.
- **Проверка требует настоящей изоляции процессов**, не повторного `import` в одном процессе Node — ES-модули кешируются, «перезапуск» одного и того же файла в одном процессе не воспроизводит то, что происходит при реальной перезагрузке страницы в браузере. Первая попытка проверки дала ложный отрицательный результат именно по этой причине.
- `outputMode` («Ауты»/«Вероятность») убран из глобальных настроек — использовался только тренировкой «Ауты», перенесён на её собственный сетап-экран, персистится в секции `outs`, не `global`.

## Защита
- Обязательная (пароли/HTTPS/токены/платёжный провайдер) — стандартные средства. Защита от копирования — принципиально не стопроцентная. Стратегия: «сделать бесполезным без сервера», не «сделать невозможным» — ценная логика (генератор Обучариума) переносится на сервер. Конфликт целей: офлайн-режим vs частая ревалидация лицензии — компромисс, ограниченный офлайн-срок. Простая мера сейчас — лимит одновременных сессий. Водяные знаки — отложено до признаков реальной проблемы. Юридическая мера — пользовательское соглашение. Общая калибровка: серьёзная защита кода — практика крупных игроков в конкурентных нишах, для небольшого продукта — дешёвый минимум сейчас, дорогие меры по факту необходимости.

## Шапка и шестерёнка настроек — построено
- **Правый кластер шапки — единая обёртка `.header-right-cluster`, не отдельный `margin-left: auto` на каждой кнопке.** Раньше `hub-compact-toggle`, `header-done-btn`, `header-gear-btn` и `header-login-btn` независимо тянули себя вправо — при одновременной видимости нескольких (или просто разном порядке скрытия/показа) авто-отступы боролись друг с другом, кнопки расползались с неровными промежутками вместо того, чтобы стоять плотной группой у правого края. Один `margin-left: auto` — на обёртке, дети внутри просто идут по порядку с обычным `gap`. Порядок внутри кластера: «i» → компакт-режим/«Готово» → шестерёнка → логин.
- **Высота шапки — зафиксирована явно (`height: 30px` на самом `header`), не выводится из высоты детей.** `hub-compact-toggle` — единственная кнопка шапки с реальной рамкой и жёстким боксом 30×30 (нужно для видимого состояния «активен»), остальные — голые SVG без рамки. Без явной высоты шапки её появление/исчезновение сдвигало высоту всей строки — реальный найденный баг.
- **Режимы шапки — централизованы в одной функции**, не разбросаны по трём роутерам. `setHeaderMainMode(isMainScreen)` в `practice-router.js` разом переключает две пары: «назад»/«i»-иконка (слева) и заголовок/логотип-вордмарк (по центру). Раньше каждый из `router.js`/`practice-router.js`/`theory.js` независимо дёргал `backBtn.classList` — из-за этого один переход (переключение вкладок) не обновлял кнопку компакт-режима хаба, реальный найденный баг.
- **Правый слот шапки — реестр, не прямая манипуляция DOM из нескольких мест.** `registerHeaderSlotUpdater`/`updateHeaderRightSlot` в `practice-router.js` (не в `router.js` — там была бы циклическая зависимость с `practice.js`).
- **Шестерёнка — отдельный, ещё более узкий случай реестра: `registerGearProvider(subviewName, openModalFn)`.** Один общий DOM-элемент на пять тренировок нельзя раздавать пяти независимым колбэкам с `classList.toggle` — реальная гонка состояний (кто вызвался последним, тот и победил), поймана до того, как стала багом. Правильное решение — одна функция (`updateGearSlot` в `practice-router.js`) сама решает, чей провайдер сейчас актуален, и сама вешает/снимает единственный обработчик клика.
- **Проверять активность экрана нужно и на уровне вкладки, и на уровне под-экрана.** Скрытый экран (`.screen`, не активный) не сбрасывает `.active` у своих внутренних под-экранов — они остаются помеченными активными, просто невидимыми. `updateGearSlot` и подобные проверки обязаны сперва убедиться, что сам экран `[data-screen="free"]` активен, и только потом смотреть на активный под-экран внутри него — иначе шестерёнка «протекает» на экраны, где её быть не должно.
- **Контракт модалки настроек (снимок + Ок/Отмена), одинаковый для всех пяти тренировок:**
  - При открытии — снимок текущих настроек (`getXSettings()`).
  - Каждое изменение поля сразу пишет в live-состояние (`state`/`posState`/`notState`/`pfState`/`comboState`) — как и раньше, никакого отдельного «черновика». Дополнительно вызывает `checkXSettingsDirty()`.
  - «Ок» активна, только если текущее состояние реально отличается от снимка (`JSON.stringify` сравнение) — не «трогали ли что-то». Если у тренировки есть валидация (например, диапазон игроков в «Позициях») — «Ок» дополнительно блокируется при невалидном состоянии, даже если оно отличается от снимка.
  - «Ок» → `persistXSettings()` (запись в `localStorage` — **только** в этот момент, не на каждое изменение) → закрыть модалку → пересоздать раздачу (`startSession`/`runXSession`).
  - «Отмена» → `applySettings(snapshot)` (откат live-состояния) → `syncXSettingsUI(snapshot)` (откат видимых переключателей — отдельный шаг, `applySettings` меняет только данные) → закрыть модалку. Сессия **не** сбрасывается, продолжается как была.
- Хаб теперь открывает все пять сессионных тренировок сразу через `startTraining(id)`, без промежуточного экрана сетапа. Кнопка «назад» из сессии этих пяти ведёт прямо в хаб (сетапа, куда возвращаться, больше нет). Калькуляторы (`calc-outs`, `calc-equity`) — не тронуты, у них по-прежнему свой отдельный сетап-экран, шестерёнки нет.
- Модалка «i» (`intro-modal`) — расширена разделом «Обратная связь» (email пока плейсхолдер, заменить на настоящий). Весь текст модалки — один `data-i18n-html`-блок на родителе; добавлять новый контент нужно **внутрь самой строки перевода**, не отдельными `data-i18n` на дочерних элементах — иначе смена языка стирает вложенные узлы при перезаписи `innerHTML` (найдено и исправлено при добавлении раздела обратной связи).
- Значок входа — SVG нарисован заново (не вырезан из растра, source-изображение имело неустранимую мягкую границу ~5–6px, проверено по пикселям). Собственный закрашенный кружок-подложка — держится одинаково хорошо на любой теме без отдельных цветовых вариантов. Вордмарк «PokerGym» — обычный текст с CSS, не картинка, по той же причине (нечёткость исходника, не задача решается перекраской/порогом).
- **Inline SVG внутри `index.html` оправдан только тогда, когда иконка реально использует `currentColor` (подстраивается под тему через CSS).** Значок входа изначально был сделан inline без единой причины — все его цвета жёстко прописаны, ни один не зависит от темы. Итог — markup внутри `index.html` раздут, а сам файл превращён в копию, которую неудобно отдать на правку отдельно (ровно так и вскрылось — попросили поправить файл, а правка ушла бы не туда). Исправлено: вынесен в `assets/logo/login-icon.svg`, подключён через `<img src="...">`. Остальные 18 inline-иконок шапки/модалок — оставлены inline, они действительно используют `currentColor`, разница обоснована для каждой отдельно, не по умолчанию.
- **Проверять реальное имя CSS-переменной, а не полагаться на память/интуицию.** Цвет «Poker» в вордмарке был завязан на `var(--fg, ...)` — переменной с таким именем в проекте не существует вообще (тема выставляет `--table-fg`, не `--fg`), поэтому всегда срабатывал запасной цвет, независимо от темы. Перед тем как писать `var(--что-то)` в новом CSS — искать (`grep`) реальное имя, которое выставляет `applyTableBg()` в `settings.js`, не угадывать по аналогии с другими проектами.
- **`.switch`/`.switch-track` (переключатели «Число», «Категория», «Скрывать карты после показа» и т.п.) — единый общий CSS-класс, инстансы идентичны пиксель-в-пиксель**, проверено измерением на реальных скриншотах (в т.ч. с 12-кратным пинч-зумом на устройстве). Видимое на сильном зуме тонкое цветное кольцо вокруг белого кружка — не баг позиционирования, а 1px `border` самого трека (`box-sizing: border-box` из глобального ресета включает бордер в заявленные 46×27px), одинаково видимый со всех сторон при достаточном увеличении. `translateX(19px)` в checked-состоянии математически точен (2px отступ + 23px кружок + 19px сдвиг = 44px — ровно ширина content-box трека за вычетом бордера). Решено не трогать — эффект незаметен при обычном масштабе использования.
