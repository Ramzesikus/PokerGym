# PokerGym — ARCHITECTURE.md

**Версия: v7**

Нумерация версий: первая содержательная правка после начала работы над Этапом 1 стала v1, и далее по нарастающей. Версия указывается только внутри самого файла — имя файла остаётся неизменным, историю версий ведёт git (`git log -- ARCHITECTURE.md`).

Это живой документ. Обновляется по ходу разработки, не разовый снимок.

**С v7 файл разделён на два** — этот (`ARCHITECTURE.md`, версия своя, отсчёт заново с v1 не делаем, продолжаем нумерацию) содержит только таблицу компонентов, структуру файлов и план. Все технические и продуктовые решения, контракты и найденные при разборе особенности — в отдельном `DECISIONS.md`, версия там своя. Причина разделения: раздел решений разросся до 208 строк (больше половины файла), стал нечитаемым — читай `DECISIONS.md`, когда нужно понять «почему так, а не иначе», этот файл — когда нужно «что где лежит и что дальше делать».

**Важная дисциплина:** таблица в разделе 1 отражает *текущее* состояние репозитория, а не план. Всё ещё не написанное — в разделе 3 (План игры / Backlog).

**Известная неточность таблицы** (не устранена в этом заходе, отдельная задача из списка «хвостов»): часть строк всё ещё показывает диапазоны строк исходного `poker-trainer_v15_35.html` и пути вида `outs-logic.js`+`outs-ui.js`, хотя по факту после интеграции Этапа 1 каждая тренировка — один файл (без разделения на `-logic`/`-ui`, см. `DECISIONS.md` и Backlog). Обновление таблицы под реальные текущие файлы — предстоит сделать отдельно.

### Точка входа для тренировок из Обучариума — техническая заметка на будущее (зафиксировано по свежей памяти, само проектирование отложено)
Не строим сам механизм сейчас — не знаем, что конкретно должен передавать урок Обучариума, пока структура уроков не продумана. Но пока контекст свежий, фиксирую, что именно должна принимать точка входа каждой реальной тренировки, когда до этого дойдёт (Этап 4):
- **outs** — категория(и) аутов, режим вывода (числа/категории/по категориям), улица (флоп/тёрн)
- **positions** — диапазон числа игроков, формат отображения (кратко/полно), школа названий (старая/новая)
- **notation** — режим (одна/несколько карт), диапазон рангов, включать ли пары, тип элемента диапазона
- **preflop-grid** — то же, что у notation, плюс сложность диапазона, что показывать (таблица/вероятность/оба), единица измерения и способ ответа для вопроса на вероятность
- **combinations** — подуровень (5 карт / рука+флоп / рука+тёрн / рука+ривер)
- **calc-outs**, **calc-equity** — не применимо: это калькуляторы с ручным вводом, не сессии с настройками, для Обучариума, вероятно, не нужны как отдельный вызов
Общая форма, которую стоит держать в голове при проектировании: `startTraining(moduleId, customSettings)`, где `customSettings` — объект с полями ровно из списка выше для конкретного `moduleId`, `null`/не передан — тренировка запускается с настройками пользователя по умолчанию (обычный сценарий из хаба «Практики»).
